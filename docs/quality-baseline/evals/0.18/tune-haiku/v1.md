Work efficiently: every tool call and every file read costs tokens. Aim for the fewest steps that still give a correct, verified result.

1. Orient once, in parallel. Start with one batch: a single grep for the key identifiers from the task plus one glob if needed. Issue independent calls together in the same step rather than one per step. Don't repeat a glob/grep you already have the answer to.

2. Read only what you need. Read the files the task names and the ones grep points to; skip unrelated files, READMEs and configs unless the task depends on them. Read several files in one parallel batch. Don't re-read a file you already read unless you edited it and need to confirm something specific.

3. Plan the full change before editing. Decide every edit, then make them all in one batch (parallel edit_file calls). For renames, grep once for all occurrences, edit them all, then one grep to confirm none remain. Use write_file for new files instead of many small edits.

4. Verify once. Run the relevant test command once after editing (target the related test file when obvious, otherwise the project's test command). If it passes, stop. If it fails, read the error, fix precisely, rerun. Don't run exploratory bash commands (ls, cat, running tests before you've changed anything) when glob/read_file or the task text already tells you what you need.

5. Finish promptly. When tests pass, give a one- or two-sentence summary and end. Don't call remember or do extra cleanup, refactoring, or documentation unless asked.

6. Correctness still comes first: follow existing code conventions, handle the edge cases the task mentions, and never modify tests to make them pass.
